# Рабочее место офицера: заявки на ремонт ВВТ

Интерактивный прототип для тестового задания. Офицер командования корпуса получает заявки на ремонт танков от бригад и решает по каждой: оформить наряд силами корпуса или переадресовать вышестоящему командованию. Цель прототипа — **ускорить обработку заявок** и убрать очередь.

Прототип собран на **SAP Fiori** — официальной библиотеке [UI5 Web Components](https://ui5.github.io/webcomponents/) (тема Horizon, шрифт SAP 72). Данные смоделированы.

## Как открыть

- **Без установки:** откройте `docs/index.html` в браузере. Это один самодостаточный файл.
- **GitHub Pages:** Settings → Pages → Branch `main`, папка `/docs`.
- **Собрать заново:**
  ```bash
  npm install
  npm run build   # результат в docs/index.html
  ```

## Где теряется время и что сделано

| Узкое место | Решение в прототипе |
|---|---|
| Внешние заявки: опечатки в номере («О» вместо 0, «З» вместо 3, латиница, тире, перестановка цифр, неполный номер) | Поиск по реестру, который прощает опечатки. Результат показан как сверка «в заявке → в реестре» с объяснением каждого исправления |
| Неточное название части («3-я мех. бригада», «1 ТБр») | Часть распознаётся по номеру и по названию |
| Номер в заявке неразборчив | Номер сверяется со вторым источником — актом технического состояния |
| Звонки в часть блокируют очередь | «Отложить»: заявка уходит во вкладку «Ждут» с таймером ожидания, просроченные подсвечиваются |
| Повторные заявки на один танк | Предупреждение, если по танку уже есть заявка или наряд, и кнопка «Закрыть как дубликат» |
| Загрузка подразделений держится в голове | Таблица сравнения трёх подразделений: может ли выполнить, сколько нарядов в работе, когда закончит. Рекомендация и подсказка переадресовать, если никто не подходит |
| Решение заполняется с нуля | Степень берётся из заключения акта, подразделение и дата предлагаются по загрузке |
| Поход к командиру на каждый наряд | Подпись пакетом: распечатать → отнести → отметить подписанные. Можно и по одному |
| Переходы между экранами | Список и заявка на одном экране, после решения сразу открывается следующая заявка, горячие клавиши |

## Ключевые UX-решения

- **Не мастер, а два шага на одной странице** («Танк» → «Решение»). Так рекомендует сам SAP Fiori для коротких ежедневных задач. Пройденный шаг сворачивается в строку с данными и кнопкой «Изменить».
- **Документы внутри шагов.** Текст заявки — в шаге «Танк», выжимка акта — в шаге «Решение», прямо над выбором степени ремонта.
- **Автовыбор танка только при уверенном совпадении:** ≥95%, явный отрыв от второго варианта и совпадение части. Иначе офицер выбирает сам. Любое действие можно отменить.

## Кастомные элементы поверх Fiori

Цвета, шрифты и отступы взяты из переменных темы Fiori. Нарисованы отдельно, потому что готовых компонентов под эти задачи нет:

- сверка «в заявке → в реестре»;
- таблица выбора подразделения с индикатором загрузки;
- шаги заявки и этапы наряда;
- выжимка и превью акта, превью наряда.

## Допущения

Это модельные значения, их нужно уточнить у заказчика:

- пороги загрузки: до 4 нарядов — низкая, 5–8 — средняя, 9+ — высокая. Последний порог взят из интервью («10 нарядов — это много»);
- условные сроки ремонта: лёгкий 5, средний 14, тяжёлый 30 дней, с поправкой на загрузку;
- порог просроченного ожидания ответа части — 2 часа;
- пакетная подпись нарядов командиром.

## Демо-заявки

| Заявка | Что показывает |
|---|---|
| З-2318 | Быстрая заявка из SAP |
| З-2319 | Буква «О» вместо нуля |
| З-2321 | Латиница и буква «З» вместо цифры 3 |
| З-2322 | Часть указана названием, переставлены цифры |
| З-2324 | Ошибка в номере части + по танку уже есть наряд |
| З-2326 | Неразборчивый номер — танк найден по акту |
| З-2327 | Танка нет в реестре, ждёт ответа части |
| З-2323, З-2329 | Тяжёлый ремонт — подходит одно подразделение |
| З-2330 | Повторная заявка на танк из З-2320 |

## Горячие клавиши

`↑` `↓` — соседняя заявка · `Enter` — подтвердить танк · `1`–`3` — подразделение · `Ctrl+Enter` — оформить наряд · `Ctrl+Shift+Enter` — оформить и подписать сразу
