# Робоче місце офіцера: заявки на ремонт ОВТ

Інтерактивний прототип для тестового завдання. Офіцер командування корпусу отримує від бригад заявки на ремонт танків і щодо кожної вирішує: оформити наряд силами корпусу чи переадресувати вищому командуванню. Мета прототипу — **пришвидшити опрацювання заявок** і прибрати чергу.

Прототип зібрано на **SAP Fiori** — офіційній бібліотеці [UI5 Web Components](https://ui5.github.io/webcomponents/) (тема Horizon, шрифт SAP 72). Дані змодельовані.

**Прототип онлайн:** https://alisakhovrina.github.io/tank-repair-officer-workplace/

## Як відкрити

- **Без встановлення:** відкрийте `docs/index.html` у браузері. Це один самодостатній файл.
- **Зібрати заново:**
  ```bash
  npm install
  npm run build   # результат у docs/index.html
  ```

## Де втрачається час і що зроблено

| Вузьке місце | Рішення в прототипі |
|---|---|
| Зовнішні заявки: помилки в номері («О» замість 0, «З» замість 3, латиниця, тире, переставлені цифри, неповний номер) | Пошук у реєстрі, що пробачає помилки. Результат показано як звірку «у заявці → у реєстрі» з поясненням кожного виправлення |
| Неточна назва частини («3-тя мех. бригада», «1 ТБр») | Частина розпізнається за номером і за назвою |
| Номер у заявці нерозбірливий | Номер звіряється з другим джерелом — актом технічного стану |
| Дзвінки в частину блокують чергу | «Відкласти»: заявка переходить на вкладку «Чекають» із таймером очікування, прострочені підсвічуються |
| Повторні заявки на один танк | Попередження, якщо на танк уже є заявка чи наряд, і кнопка «Закрити як дублікат» |
| Завантаження підрозділів тримається в голові | Таблиця порівняння трьох підрозділів: чи може виконати, скільки нарядів у роботі, коли закінчить. Рекомендація і підказка переадресувати, якщо жоден не підходить |
| Рішення заповнюється з нуля | Ступінь береться з висновку акта, підрозділ і дата пропонуються за завантаженням |
| Похід до командира з кожним нарядом | Підпис пакетом: надрукувати → віднести → позначити підписані. Можна й по одному |
| Переходи між екранами | Список і заявка на одному екрані, після рішення одразу відкривається наступна заявка, гарячі клавіші |

## Ключові UX-рішення

- **Не майстер, а два кроки на одній сторінці** («Танк» → «Рішення»). Так рекомендує сам SAP Fiori для коротких щоденних задач. Пройдений крок згортається в рядок із даними та кнопкою «Змінити».
- **Документи всередині кроків.** Текст заявки — у кроці «Танк», витяг з акта — у кроці «Рішення», просто над вибором ступеня ремонту.
- **Автовибір танка лише за впевненого збігу:** ≥95%, явний відрив від другого варіанта і збіг частини. Інакше офіцер обирає сам. Будь-яку дію можна скасувати.

## Кастомні елементи поверх Fiori

Кольори, шрифти й відступи взято зі змінних теми Fiori. Окремо намальовано те, для чого готових компонентів немає:

- звірка «у заявці → у реєстрі»;
- таблиця вибору підрозділу з індикатором завантаження;
- кроки заявки та етапи наряду;
- витяг і прев'ю акта, прев'ю наряду.

## Припущення

Це модельні значення, їх треба уточнити в замовника:

- пороги завантаження: до 4 нарядів — низьке, 5–8 — середнє, 9+ — високе. Останній поріг узято з інтерв'ю («10 нарядів — це багато»);
- умовні строки ремонту: легкий 5, середній 14, важкий 30 днів, з поправкою на завантаження;
- поріг простроченого очікування відповіді частини — 2 години;
- пакетний підпис нарядів командиром.

## Демо-заявки

| Заявка | Що показує |
|---|---|
| З-2318 | Швидка заявка з SAP |
| З-2319 | Літера «О» замість нуля |
| З-2321 | Латиниця і літера «З» замість цифри 3 |
| З-2322 | Частину вказано назвою, переставлено цифри |
| З-2324 | Помилка в номері частини + на танк уже є наряд |
| З-2326 | Нерозбірливий номер — танк знайдено за актом |
| З-2327 | Танка немає в реєстрі, чекає відповіді частини |
| З-2323, З-2329 | Важкий ремонт — підходить один підрозділ |
| З-2330 | Повторна заявка на танк із З-2320 |

## Гарячі клавіші

`↑` `↓` — сусідня заявка · `Enter` — підтвердити танк · `1`–`3` — підрозділ · `Ctrl+Enter` — оформити наряд · `Ctrl+Shift+Enter` — оформити й підписати одразу
